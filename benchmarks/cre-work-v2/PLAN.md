# CRE Work v2: execution and qualification plan

Authorized by the publisher on 2026-09-07. This expands the existing financing
and supplied-record research pilots. This document is a plan, not a result.

## Scope

1. Messy deal-room ingestion: original documents, authoritative-version
   selection, unit-type breakdowns, page/cell citations, conflicting sources.
2. Complete underwriting and offering-memorandum production: actual editable
   workbooks and readable PDFs, financial accuracy, and cross-file agreement.
3. Deal revisions: a later source/assumption update in the same conversation;
   correct propagation and preservation of unaffected approved content.
4. Underwriting judgment: material risks, missing information, appropriate
   qualifications, and false alarms on clean control cases.
5. Live comps and lead discovery: actual retrieval, dated evidence, entity
   resolution, verified precision and audited pooled coverage.
6. Lender qualification: dated program requirements, hard eligibility
   constraints, support for recommendations, and missing-information handling.

Target: 20 distinct deal packets across multifamily, office, retail and
industrial; initial delivery plus a material revision; three trials per
condition. Live discovery uses separately frozen briefs. Report stage, case,
condition and trial coverage explicitly. Partial execution must not appear as
a complete run of this target.

## Conditions and attribution

Evaluate native Lev in the authorized Kyle Graves test account, GPT-5 and
Claude Opus 5 APIs with a shared public file/calculation harness, a baseline
using Lev's recorded underlying model when available, and actual consumer
agent products when accessible. Record exact requested and returned model
identifiers and product/version labels. No silent substitutions.

Separate matched-input analysis from actual-product discovery/data-access
conditions. Record all enabled tools, sources, context, input representations
and account entitlements. Do not infer identical access from identical briefs.
Raw API controls without file tools do not receive work-product scores.

## Qualification and publication

Private customer materials may inform realistic task design and authorized
internal testing. Their presence in Drive is not a public redistribution
license. Keep original customer files and identifying derived answers outside
the public repository until release rights are documented. Publish original
synthetic fixtures under the project license and label them accurately.

Independent CRE reviewers must qualify each reference solution and rubric
before a practitioner-qualified release. Provider identities are hidden for
professional-readiness grading. Automated checks and author review can proceed
with their actual status disclosed. Human acceptance, correction time and
inter-reviewer agreement remain unmeasured until humans complete the work.

Freeze inputs, briefs, reference keys, grader code, allowed assistance, retry
rules and run matrix before scored calls. Use fresh evaluation deals, with
whole-deal separation from development examples. Changes after outcomes are
visible require a new scoring version with original scores retained. Preserve
every attempted condition, failure, retry and original output.

## Metrics

- Field correctness and source-location support; critical factual errors.
- Work-product acceptance with a separate hard gate for material financial
  errors; presentation cannot offset a financial failure.
- Revision propagation and unchanged-content preservation.
- Risk precision/recall against adjudicated known issues, with clean controls.
- Verified precision for live discovery; coverage against an independently
  audited pooled candidate set, never claimed web-wide recall.
- Analyst verification/correction minutes and acceptance without material
  correction, measured only through documented human review.
- Time and attributable inference, tool/data and human costs per accepted
  deliverable; report missing cost components explicitly.
- First-attempt success and all-three-trials success; case-level uncertainty,
  retaining family/deal clustering in any aggregate.

## Spending and operational limits

The user's existing $200 token authorization is cumulative, not reset by this
expansion. Reconcile previous usage and reserve unknown charges conservatively
before new paid calls. Freeze a staged run order before seeing outputs and stop
dispatch at the remaining spending ceiling; do not select only favorable runs.
No paid professional-review commitment or new product subscription is assumed.

Native tests create clearly named benchmark-only content in the test account.
No external outreach, customer deal edits or lender placements are part of the
benchmark. Artifacts are examined as delivered; file-serialization defects are
attributed to the harness when the original model output proves that cause.

## Delivery

Release all six track definitions, case manifests, public adapters, graders,
blind review packets, run/cost ledgers, coverage reporting, charts and narrative
findings. Professional qualification, authentic-source release permission,
consumer-product access and full repeated-cohort execution are separate
completion gates and must be reported truthfully.
