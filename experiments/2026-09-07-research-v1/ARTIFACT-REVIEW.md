# Supplementary artifact observations

The frozen four-check artifact score covers required file format, selected identities/order, selected facts/explicit unknowns, and source identifiers. It is not a complete assessment of every extra cell, visual layout, or investment-use readiness. These additional observations are disclosed without changing the primary rubric or repairing originals.

- **GPT-5 with tools, rent-comps-birch and rent-comps-cypress:** the original annual-increase cell contains 2.5 with percentage formatting, so the rendered workbook displays 250.0%. The source specifies 2.5%. Required effective-rent outputs can still be numerically correct; the extra assumption display is misleading. Inspect the original files and creation tool specifications.
- **General-agent comp grids:** several rendered subtitles and long column headings are clipped or compressed. The shared generic workbook writer contributes to layout constraints. These results therefore measure the particular shared file harness as well as the model's specification.
- **Lev rent-comps-cypress:** the rendered excerpt clips long entity identifiers and text. Other native grids provide more usable column widths or wrapping. Original cell values remain available in the downloadable XLSX; no formatting repairs were applied.
- **No-match cases:** an empty grid or a grid where every candidate is explicitly rejected can both faithfully represent an empty shortlist. The artifact mapper recognizes these representations uniformly. An unknown or blank eligibility cell is not an explicit rejection.

Workbook excerpts are rendered with the bundled artifact runtime from the original XLSX bytes. Rendering itself can differ from desktop Excel. It does not rewrite the original workbook. The inspection script records the source SHA-256, sheet and range; it is available at `tools/render-research-artifacts.py`.

The public answer grader and its pre-execution hash are unchanged. Equivalent CSV/XLSX header labels are mapped uniformly during artifact inspection. Blank null exports are delivery-annotation failures rather than asserted numeric values.

The artifact mapper was implemented during the audit, after some outputs were visible. The four acceptance criteria and explicit-null requirement were frozen beforehand. Presentation mappings apply uniformly to every condition; the pre-execution factual grader was not changed.

The generic CSV writer in the frozen harness serializes Python `None` (model-supplied JSON `null`) as a blank cell. Where original tool inputs prove this happened, field audits explicitly attribute the lost unknown annotation to `benchmark_csv_serializer`, with the original tool log linked. These failures remain in end-to-end delivery scores but are not model factual or reasoning failures. The scored writer and original outputs are not repaired after execution. A future harness version should emit an explicit unknown marker.

All 36 final comp workbooks (12 native and 24 generic-agent files) were rendered as original sheet excerpts and visually inspected. Other delivered versions remain retained. The final sales-comp exports show readable data rows, with some generic-agent notes, source text and headers clipped by fixed column widths. These presentation observations are separate from the four consistency checks.
